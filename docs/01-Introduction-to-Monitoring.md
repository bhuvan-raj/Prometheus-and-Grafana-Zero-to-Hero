Monitoring & Observability

Before learning Prometheus and Grafana, it is important to understand what monitoring is, what observability is, and how they are used in real-world systems.

⸻

1. What is Monitoring?

Monitoring is the process of continuously collecting and observing information about a system to determine its health, performance, and availability.

For example, we can monitor:

* CPU utilization
* Memory utilization
* Disk usage
* Network traffic
* Application response time
* Request count
* Error rate
* Service availability

Example

Suppose an application server has:

CPU Usage       → 92%
Memory Usage    → 87%
Disk Usage      → 78%
Error Rate      → 15%
Response Time   → 4.2 seconds

Monitoring helps us identify that something is wrong and allows us to take action.

⸻

2. Why Do We Need Monitoring?

Modern applications are distributed across multiple components:

Users
  │
  ▼
Load Balancer
  │
  ├──────────────┐
  ▼              ▼
Application 1   Application 2
  │              │
  ├──────┬───────┘
  ▼      ▼
Database  Cache

Without monitoring, it becomes difficult to know:

* Is the application running?
* Is the server overloaded?
* Is the database responding?
* Are requests failing?
* Is the application becoming slower?
* Which component is causing the problem?

Monitoring gives us visibility into the health and performance of these systems.

⸻

3. What is Observability?

Observability is the ability to understand the internal state of a system by analyzing the data it produces.

In simple terms:

Monitoring tells us that something is wrong. Observability helps us understand why it is wrong.

Example

Monitoring may tell us:

CPU Usage: 95%

Observability helps us investigate further:

CPU Usage: 95%
        ↓
Which service?
        ↓
Which process?
        ↓
Which request?
        ↓
Which operation?
        ↓
Why is it consuming so much CPU?

Observability is particularly important in distributed and microservice-based environments.

⸻

4. Monitoring vs Observability

Monitoring	Observability
Tells us what is happening	Helps us understand why it is happening
Focuses on known failure conditions	Helps investigate unknown problems
Uses predefined metrics and alerts	Correlates multiple telemetry signals
Health and performance focused	System behavior and troubleshooting focused
Example: CPU > 90%	Example: Why is this service causing high CPU?

A useful way to remember it:

Monitoring
    ↓
Something is wrong
    ↓
Observability
    ↓
Why is it wrong?

Monitoring and observability are complementary, not competing concepts.

5.1 Metrics

Metrics are numerical measurements collected over time.

Examples:

CPU Usage       → 75%
Memory Usage    → 62%
Request Count   → 15,420
Error Rate      → 2.4%
Response Time   → 250 ms

Metrics are useful for:

* Monitoring system health
* Creating dashboards
* Detecting trends
* Creating alerts
* Capacity planning

Example

CPU Usage
100% ┤
 80% ┤              ╭──╮
 60% ┤        ╭─────╯  ╰──
 40% ┤────────╯
 20% ┤
     └──────────────────────
             Time

Popular Metrics Tools

* Prometheus
* Grafana
* Datadog
* Amazon CloudWatch
* Zabbix
* Nagios

In this repository, we will primarily use:

Prometheus + Grafana

⸻

5.2 Logs

Logs are records of events generated by applications, servers, containers, and other systems.

Example:

2026-08-09 10:15:21 INFO User login successful
2026-08-09 10:16:03 ERROR Database connection failed
2026-08-09 10:16:04 WARN Retrying database connection

Logs provide detailed information about what happened inside a system.

They are particularly useful for:

* Application debugging
* Error investigation
* Security investigation
* Troubleshooting
* Auditing

Popular Logging Tools

* Grafana Loki
* Elasticsearch
* Logstash
* Fluent Bit
* Fluentd
* OpenSearch
* Splunk

⸻

5.3 Traces

Traces show the journey of a request through a distributed system.

Consider an e-commerce application:

User
 │
 ▼
API Gateway
 │
 ▼
Order Service
 │
 ├──────────────┐
 ▼              ▼
Payment       Inventory
Service       Service
 │
 ▼
Database

A trace can show how a single request traveled through these services.

For example:

Request
│
├── API Gateway       20 ms
│
├── Order Service     80 ms
│
├── Payment Service  150 ms
│
├── Inventory         40 ms
│
└── Database          30 ms
Total: 320 ms

This helps us identify where latency is coming from.

Popular Tracing Tools

* Grafana Tempo
* Jaeger
* Zipkin
* OpenTelemetry
* Datadog
* AWS X-Ray

11. Key Takeaways

Monitoring

Continuously collecting and observing system information to detect health and performance problems.

Observability

The ability to understand the internal state and behavior of a system from the telemetry it produces.

Three Pillars

Metrics → What is happening?
Logs    → What happened?
Traces  → Where did it happen / where was time spent?

Core Tools

Metrics  → Prometheus
Logs     → Loki
Traces   → Tempo
Visualize → Grafana
Collect  → Alloy / OpenTelemetry
